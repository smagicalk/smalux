# 系统采集任务

Agent 中 `tasks/collect/collectors/` 负责读取原始平台数据，`tasks/collect/` 中的固定 Task 负责应用
Proto 配置并返回 `TaskResult`。所有采样结果携带 `SampleMetadata`：采样开始时间，以及存在上一样本时
的采样间隔。

## 支持类型

| Task | 配置重点 | 结果 |
| --- | --- | --- |
| System | 组合开关和筛选 | 主机、CPU、内存、负载、I/O、IP、Socket、进程摘要。 |
| CPU | 采样行为 | 拓扑、频率、总使用率和逻辑 CPU 使用率。 |
| Memory | 无复杂筛选 | 物理内存和交换区容量与使用量。 |
| Load | 平台支持情况 | 1、5、15 分钟平均负载。 |
| Host | 主机静态属性 | 主机名、系统、内核、架构、启动时间。 |
| Disk I/O | 设备名、挂载点 include/exclude | 容量、累计计数、增量和速率。 |
| Network I/O | 网卡 include/exclude | 字节、数据包、错误计数、增量和速率。 |
| Local IP | 网卡筛选 | 本机接口 IPv4/IPv6 地址。 |
| Public IP | IPv4/IPv6 族选择 | 外部服务解析得到的公网地址。 |

## 选择规则

网卡和磁盘都采用相同优先级：

1. 任一 include 非空时进入白名单模式，只保留明确包含项。
2. 再应用 exclude；同一项同时匹配 include 和 exclude 时，exclude 最终优先。
3. include 全部为空时默认选择全部，再应用 exclude。

网卡必须使用完整接口名，例如 `Ethernet`、`eth0`；磁盘可按完整设备名或完整挂载点选择。使用完整匹配
可以避免模糊名称意外采集其他设备。

## 增量与速率

磁盘和网络的速率不是单次系统调用直接返回，而是当前累计计数减去同一 Task 上次样本，再除以实际
采样间隔。因此：

- 首次采样通常只有累计值，没有可靠增量速率；
- Task 实例重建后需要重新预热；
- 系统计数器回绕或设备重建时实现必须避免产生负增量；
- Scheduler 延迟会改变实际采样间隔，不能只使用配置周期计算速率。

## 各类结果如何读取

### CPU、内存与负载

CPU 结果包含物理/逻辑 CPU 数、全局使用率，以及每个逻辑 CPU 的名称、品牌、厂商、频率和使用率。
`warmed_up = false` 时，本次结果还没有可靠的前一样本，使用率只适合展示为“预热中”。

内存结果以字节返回物理内存的总量、已用、可用和空闲量，同时包含使用率与 Swap 容量。不同操作系统
对 available 和 free 的定义不同，跨平台图表应优先使用协议直接给出的 used/available，不要自行混算。

负载结果返回 1、5、15 分钟平均值，并带 `supported`。不支持该概念的平台应展示“不支持”，不能把三个
零值解释为机器完全空闲。

### Host

Host 结果包含主机名、操作系统名称与版本、内核版本、CPU 架构、运行时长和启动时间。这类字段变化少，
通常无需与 CPU 使用率使用相同的高频周期。

### Disk I/O

每个磁盘条目可包含设备名、挂载点、容量、累计读写字节/次数，以及存在前一样本时的区间增量和每秒速率。
设备被移除、重新挂载或计数器回绕后，新基线应重新预热，不能产生负吞吐。

例如，只采集数据盘并排除临时挂载点时，可以把数据盘的完整设备名或挂载点放入 include，再将明确不需要
的挂载点放入 exclude。exclude 始终优先，因此可在较宽白名单上做最终剔除。

### Network I/O 与 IP

网卡结果包含接口名、MAC、MTU、累计收发字节/包/错误，以及区间增量和速率。虚拟网卡、容器网桥和
Loopback 往往需要通过 exclude 明确排除，否则汇总时可能重复计算业务流量。

Local IP 结果按接口返回地址、前缀长度和地址作用域。地址列表可能同时存在 IPv4、IPv6、链路本地地址；
调用方应根据 scope 展示或筛选，而不是默认取第一项。

## System Task 的取舍

System Task 适合低频主机概览，但一次组合多个 Collector，成本和结果体积都更高。高频监控建议拆成
独立 Job：CPU/内存可以较高频，磁盘容量和 Host 信息可以较低频，进程与 Socket 详情按需运行。

当前 `SystemTaskConfig` 只对磁盘、网络和 Local IP 暴露筛选配置；组合结果还会包含 Host、CPU、Memory、
Load、Socket 与 Process 摘要。System Task 不会隐式访问外部公网 IP 服务，公网地址必须使用独立的
Public IP Task 请求。

## 周期建议

以下仅是初始值，最终应按机器规模和可接受开销压测：

| 数据 | 起始周期 | 说明 |
| --- | --- | --- |
| CPU、Memory、Load | 5-15 秒 | 适合趋势监控；过短会增加调度和上报开销。 |
| Disk/Network I/O | 10-30 秒 | 需要稳定的前后样本计算速率。 |
| Host、磁盘容量 | 5-30 分钟 | 属性变化低频。 |
| Local IP | 1-5 分钟 | 网络重配时需要及时发现，但无需秒级扫描。 |
| Public IP | 5-30 分钟 | 涉及外部 DNS 和服务，应更低频并限制重试。 |
| System 组合快照 | 30-60 秒 | 用于概览，不替代高频独立指标。 |

## Public IP

公网 IP Task 会访问外部解析服务，可选择：

- 同时查询 IPv4 和 IPv6；
- 仅 IPv4；
- 仅 IPv6。

它与 Local IP Task 不同，会引入外部网络依赖、DNS、代理和服务可用性风险。生产环境应配置超时、
重试和允许访问的服务，并避免把临时失败解释为主机没有公网地址。

结果状态应区分 `NOT_REQUESTED`、`RESOLVED` 与 `FAILED`。例如只请求 IPv4 时，IPv6 的
`NOT_REQUESTED` 是配置结果，不是故障；只有 `FAILED` 才应进入错误统计。
